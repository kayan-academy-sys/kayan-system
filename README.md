# نظام كيان — نظام متكامل لإدارة مركز تدريبي

تطبيق ويب عربي (RTL) لإدارة أكاديمية كيان: المبيعات والعملاء المحتملين، الكورسات والمجموعات والمحاضرات، الباقات والحجوزات، الحسابات والأقساط والمصروفات، الاستقبال والحضور، الأتمتة الداخلية، التقارير، ومساعد ذكي للموظفين.

## التقنيات
Node.js + Express + EJS (واجهة عربية RTL بخط Cairo بهوية كيان: تركواز ‎#006776→#018a94 وبرتقالي ‎#fc8400) + PostgreSQL. الأتمتة داخل التطبيق (بدون n8n) عبر مؤقت داخلي أو نقطة cron خارجية.

## التشغيل محليًا
```bash
cp .env.example .env   # واملأ القيم
npm install
npm run migrate
npm run seed -- --demo # ينشئ مدير النظام + بيانات تجريبية (موظفون بكلمة مرور staff123456)
npm start              # http://localhost:3000
```

## الدخول وإدارة المستخدمين
- لا يوجد تسجيل ذاتي. مدير النظام الأصلي يُنشأ من `ADMIN_EMAIL`/`ADMIN_PASSWORD` عند أول تشغيل للـ seed.
- المدير ينشئ **دعوة** من صفحة «المستخدمون» بإدخال بريد الموظف ودوره، ويرسل له رابط الدعوة (يُنسخ من الشاشة؛ يمكن ربط SMTP لاحقًا لإرساله بالبريد تلقائيًا). الموظف يعيّن كلمة مروره من الرابط.
- المشرف العام لا يضيف مستخدمين مباشرة؛ يقدّم **طلب إضافة** يوافق عليه المدير أو يرفضه. لا يمكن تعطيل أو تعديل صلاحيات مدير النظام الأصلي.

## الأدوار
مدير النظام، مشرف عام، مدير مبيعات، **تيم ليدر مبيعات** (يرى نشاط كل موظفي المبيعات بالتفصيل من «متابعة الفريق»)، موظف مبيعات، مدير حسابات، موظف حسابات، استقبال، مسؤول كورسات ومجموعات. الصلاحيات مفروضة على الخادم (وليست على الواجهة فقط) وتُسجل العمليات الحساسة في سجل المراجعة.

## توزيع العملاء وواتساب
- العملاء الجدد يُسندون آليًا بالتساوي لموظفي المبيعات **الحاضرين** (تُحدد الحضور يوميًا من «توزيع العملاء»).
- من لم يحجز خلال مدة الإسناد (90 يومًا افتراضيًا، قابلة للضبط من الإعدادات) يُحوّل تلقائيًا لموظف آخر مع حفظ سجل الإسناد وإشعار بالتاريخ السابق. حالة «خسرنا العميل» مستثناة افتراضيًا وقابلة للضبط.
- **ربط واتساب الفعلي لاحقًا**: وجّه رسائل واتساب الواردة إلى `POST /api/webhooks/whatsapp` بترويسة `x-webhook-secret` والجسم `{phone,name,text}`. يُنشأ العميل (بربطه بملف موجود إن تطابق الهاتف) ويُوزع آليًا. راجع `src/integrations/whatsapp/adapter.js`.

## القواعد المالية
- لا حذف نهائي للعمليات المالية: الإلغاء/العكس المالي بسبب موثق وبصلاحية مدير الحسابات أو المدير.
- التقسيط: المقدم + مجموع الأقساط = إجمالي السعر إجباريًا، والرصيد يتحدث تلقائيًا مع كل دفعة.
- التحويل بين الحسابات حركة داخلية وليس مصروفًا/إيرادًا. إقفال يومي للخزينة مع حفظ لقطة الأرصدة.

## الأتمتة
تعمل كل 15 دقيقة (على خادم دائم `RUN_CRON=true`) أو عبر `POST /api/cron/run` بترويسة `x-cron-secret` (مثلًا من cron-job.org على الاستضافة السحابية) أو كسولًا مع الطلبات في serverless. المهام: تذكير المتابعات، تحويل العملاء بعد انتهاء المدة، تنبيهات الأقساط، اكتمال المجموعات. النتائج في صفحة «الأتمتة» و`job_runs`.

## مساعد كيان (AI)
مساعد داخلي يجيب من قاعدة البيانات مباشرة (أقساط متأخرة، محاضرات اليوم، مجموعات متاحة، تحصيل، بيانات عميل بالرقم، إرشادات الاستخدام). لربط نموذج خارجي اضبط `AI_API_KEY`/`AI_API_URL` — نقطة الربط موثقة في `src/routes/assistant.js`.

## النسخ الاحتياطي والاستعادة
```bash
DATABASE_URL=... ./scripts/backup.sh    # نسخة مضغوطة، تحفظ آخر 30 نسخة
DATABASE_URL=... ./scripts/restore.sh backups/kayan-XXXX.dump
```
على Neon: تتوفر استعادة لنقطة زمنية من لوحة Neon أيضًا. جرّب الاستعادة دوريًا على قاعدة اختبار.

## النشر (مجاني)
1. **قاعدة البيانات**: Neon (خطة مجانية) — أنشئ مشروعًا وانسخ رابط `DATABASE_URL`.
2. **التطبيق — خيار Render (مستودع + render.yaml)**: New > Blueprint واختر المستودع، واضبط `DATABASE_URL`. الخطة المجانية تنام بعد خمول 15 دقيقة وتوقظها أول زيارة.
3. **خيار Vercel (serverless)**: `npx vercel` مع متغيرات البيئة؛ المهام تعمل عبر `/api/cron/run` أو بشكل كسول.
